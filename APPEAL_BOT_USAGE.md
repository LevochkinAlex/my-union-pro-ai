# Appeal Bot - Руководство по использованию

## Обзор

Appeal Bot - это специализированный AI-ассистент для обработки обращений в профсоюз. Он позволяет пользователям создавать обращения разных типов в отдельных сессиях/вкладках.

## Типы обращений

Appeal Bot поддерживает следующие типы обращений:

1. **LEGAL** (Юридические) - правовые вопросы, трудовые споры
2. **ACCOUNTING** (Бухгалтерские) - вопросы по взносам, финансам
3. **TECHNICAL** (Технические) - технические проблемы, доступ к системе
4. **OTHER** (Прочие) - общие вопросы

## Создание обращений в разных вкладках

### Как это работает:

1. **Новое обращение**: Пользователь нажимает кнопку "Новое обращение" в меню чата
2. **Создание сессии**: Система создает новую `ChatSession` с типом `APPEAL`
3. **Уникальная вкладка**: Каждое обращение открывается в своей вкладке с уникальным `sessionId`
4. **Независимые обращения**: Пользователь может иметь несколько открытых обращений одновременно

### API Endpoints:

```typescript
// Создать новую сессию обращения
POST /api/chat/sessions
Body: { type: "APPEAL", title: "Обращение №12345678" }
Response: { session: { id, title, type, createdAt } }

// Создать обращение с деталями
POST /api/appeals
Body: { type: "LEGAL", title: "...", description: "..." }
Response: { appeal: { id, publicId, type, status, ... } }
```

## Настройка Appeal Bot

### Обязательные поля:

1. **name**: "Appeal Bot" (или другое имя)
2. **model**: Модель AI (например, "openai/gpt-4o-mini")
3. **apiProviderId**: ID API провайдера (OpenRouter, OpenAI и т.д.)
4. **systemPrompt**: Специализированный промпт для обработки обращений
5. **knowledgeBaseIds**: Связь с базой знаний профсоюза

### Системный промпт:

Appeal Bot использует специальный промпт, который:

- ✅ Фокусируется на решении конкретных проблем пользователя
- ✅ Использует базу знаний профсоюза (устав, положения, законы РФ)
- ✅ Предоставляет профессиональную помощь
- ❌ НЕ предлагает вступить в профсоюз (это задача другого бота)
- ❌ НЕ просит заполнить профиль (пользователь уже член)

## Функции

### 1. Множественные обращения

Пользователь может создать несколько обращений одновременно:

```
Мой бот (STATEMENT) - для заявлений о вступлении
└─ Обращение №10234567 (APPEAL) - юридический вопрос
└─ Обращение №10234568 (APPEAL) - бухгалтерский вопрос
└─ Обращение №10234569 (APPEAL) - технический вопрос
```

### 2. Связь с ChatMessage

Все сообщения в обращении связываются:

```typescript
ChatMessage {
  sessionId: "session_123",
  appealId: "appeal_456", // опциональная связь
  chatBotId: "appeal_bot_789",
  role: "user" | "assistant",
  content: "..."
}
```

### 3. Аналитика

Система собирает аналитику по обращениям:

- Количество обращений по типам
- Распространенные ключевые слова
- Среднее время решения
- Статусы обращений

## База знаний

Appeal Bot использует базу знаний, которая включает:

### Документы профсоюза:

- Устав профсоюза
- Положения (ПДК, ППО, ШПА и т.д.)
- Методические пособия
- Инструкции
- Формы документов

### Форматы:

- DOCX, DOC
- PDF
- XLS, XLSX
- JPG (для сканов документов)

## Troubleshooting

### Ошибка: "Не удалось обновить бота"

**Причина**: Пустая или невалидная модель

**Решение**:
1. Убедитесь, что выбран API Provider
2. Выберите модель из выпадающего списка
3. Сохраните изменения

### Ошибка: "Модель должна быть непустой строкой"

**Причина**: Модель не выбрана или передается как объект

**Решение**:
1. Проверьте, что `providerModels` содержит строки, а не объекты
2. В коде frontend убедитесь, что передается `modelId`, а не весь объект

### Обращения не создаются

**Причина**: Appeal Bot не связан с сессией правильно

**Решение**:
1. Проверьте тип сессии: `type: "APPEAL"`
2. Убедитесь, что в `/api/chat/route.ts` правильно определяется `sessionType`
