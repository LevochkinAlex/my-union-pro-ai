# ✅ Универсальная система контекстной валидации

> **Дата:** 24 ноября 2025  
> **Проблема:** Организации и адреса не валидировались, когда пользователь отвечал на вопрос бота (без ключевых слов в ответе)

---

## 🐛 Проблема

### Было:

```typescript
// Старая логика: поиск по ключевым словам в сообщении пользователя
if (message.toLowerCase().includes("организац") || 
    message.toLowerCase().includes("работаю")) {
  // Поиск организации
}
```

**Пример:**
```
BOT: Укажите наименование организации, в которой вы работаете.
USER: БСМП челны           <-- НЕТ ключевых слов!
BOT: Я нашел вашу организацию: БСМП челны  <-- Просто повтор, не валидировано!
```

❌ **Проблема:** Когда пользователь просто отвечает на вопрос бота (без ключевых слов), валидация не запускается!

---

## ✅ Решение: Контекстная валидация

### Новая архитектура:

```
┌─────────────────────────────────────────────────────┐
│  1. Определить КОНТЕКСТ последнего вопроса бота     │
│     (о чем он спрашивал?)                           │
└────────────────┬────────────────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────────────────┐
│  2. Валидировать ответ пользователя                 │
│     через внешние API (DaData, Минюст)              │
└────────────────┬────────────────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────────────────┐
│  3. Улучшить сообщение для AI                       │
│     (добавить валидированные данные)                │
└─────────────────────────────────────────────────────┘
```

---

## 🔧 Техническая реализация

### 1. Файл `lib/chat-context-helpers.ts`

Новый модуль с функциями:

#### `detectBotQuestionContext(lastBotMessage)`
Определяет контекст последнего вопроса бота.

**Пример:**
```typescript
const lastMsg = {
  role: "assistant",
  content: "Укажите наименование организации, в которой вы работаете."
};

const context = detectBotQuestionContext(lastMsg);
// Результат: "ORGANIZATION"
```

#### `enhanceUserMessageWithContext(userMessage, context, validatedData)`
Улучшает сообщение пользователя, добавляя контекст и валидированные данные.

**Пример для ORGANIZATION:**
```typescript
const enhanced = enhanceUserMessageWithContext(
  "БСМП челны",
  "ORGANIZATION",
  {
    organization: {
      name: "ГОСУДАРСТВЕННОЕ АУ ЗДРАВООХРАНЕНИЯ РЕСПУБЛИКИ ТАТАРСТАН БОЛЬНИЦА СКОРОЙ МЕДИЦИНСКОЙ ПОМОЩИ ИМЕНИ Р.С.АКЧУРИНА",
      foundInDatabase: false,
    }
  }
);

// Результат:
// БСМП челны
// 
// ---
// ✅ ОРГАНИЗАЦИЯ НАЙДЕНА В РЕЕСТРЕ МИНЮСТА РФ:
// [VALIDATED_ORGANIZATION: ГОСУДАРСТВЕННОЕ АУ...]
// 
// ОБЯЗАТЕЛЬНО покажи пользователю ПОЛНОЕ официальное название...
// ---
```

#### `requiresValidation(context)`
Проверяет, нужна ли валидация для контекста.

**Пример:**
```typescript
requiresValidation("ORGANIZATION"); // true
requiresValidation("ADDRESS");      // true
requiresValidation("FIO");          // false
```

#### `logContext(context, userMessage)`
Логирует контекст для отладки.

**Пример:**
```typescript
logContext("ORGANIZATION", "БСМП челны");
// Лог: [chat-context] 🏢 Detected context: ORGANIZATION | User message: "БСМП челны"
```

### 2. Интеграция в `app/api/chat/route.ts`

**Было (600+ строк кода с дублированием):**
```typescript
// Проверка адреса
if (message.includes("адрес") || message.includes("ул.") || ...) {
  // Валидация адреса
}

// Проверка организации
if (message.includes("организац") || message.includes("работаю") || ...) {
  // Поиск организации
}
```

**Стало (30 строк универсального кода):**
```typescript
// Определяем контекст
const lastBotMessage = chatHistory[chatHistory.length - 1];
const questionContext = detectBotQuestionContext(lastBotMessage);

// Валидируем если нужно
const validatedData = {};
if (requiresValidation(questionContext)) {
  if (questionContext === "ADDRESS") {
    validatedData.address = await validateAddressWithDaData(message);
  }
  if (questionContext === "ORGANIZATION") {
    validatedData.organization = await findOrganization(message, region);
  }
}

// Улучшаем сообщение
const enhancedMessage = enhanceUserMessageWithContext(
  message,
  questionContext,
  validatedData
);
```

## 📊 Преимущества новой системы

### 1. **Универсальность** ✅
- Одна функция `detectBotQuestionContext()` для всех типов вопросов
- Легко добавить новые контексты (просто добавить в enum и условие)

### 2. **Автоматическая валидация** ✅
- Система **сама определяет**, когда нужна валидация
- Не нужно угадывать ключевые слова в ответе пользователя

### 3. **Меньше кода, больше функциональности** ✅
**Было:**
- 2 отдельных блока валидации (адрес + организация)
- ~150 строк кода
- Дублирование логики

**Стало:**
- 1 универсальный блок
- ~30 строк кода
- Вся логика в отдельном модуле

### 4. **Лучшая отладка** ✅
```
[chat-context] 🏢 Detected context: ORGANIZATION | User message: "БСМП челны"
[chat] 🔍 Searching organization in Minjust registry: БСМП челны | Region: Татарстан
[chat] ✅ Organization found: ГОСУДАРСТВЕННОЕ АУ... | In DB: false
```

Каждый шаг виден в логах с эмодзи!

### 5. **Расширяемость** ✅
Чтобы добавить валидацию **нового типа данных**:

1. Добавить в `BotQuestionContext`:
   ```typescript
   export type BotQuestionContext = 
     | "ORGANIZATION"
     | "ADDRESS"
     | "NEW_TYPE"  // 👈 Новый тип
     | ...
   ```

2. Добавить определение контекста:
   ```typescript
   if (content.includes("ключевое слово")) {
     return "NEW_TYPE";
   }
   ```

3. Добавить обработку:
   ```typescript
   case "NEW_TYPE":
     enhanced = `${userMessage}\n\n[Контекст для NEW_TYPE]`;
     break;
   ```

4. Готово! ✅

## ⚠️ Важные замечания

### 1. Порядок вопросов имеет значение
Система анализирует **последнее** сообщение бота. Если бот задал несколько вопросов подряд, учтется только последний.

### 2. Валидация только для основных полей
Валидация через внешние API работает только для:
- ✅ Организация (Минюст РФ / DaData)
- ✅ Адрес (DaData)

Остальные поля сохраняются как есть (но с контекстными подсказками для AI).

### 3. Регион должен быть указан
Для более точного поиска организаций **регион должен быть заполнен** в профиле пользователя. Если регион не указан, поиск все равно работает, но может быть менее точным.

### 4. Кеширование не используется
Каждый запрос к DaData и Минюсту выполняется заново. Если нужно кеширование - добавить Redis.
