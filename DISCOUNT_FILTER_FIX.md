# Исправление фильтра скидок

## Проблема

Пользователь сообщил: "В мои скидки https://myunion.pro/dashboard/discounts очень плохо работает фильтр, если выбирать город то туда попадают не все скидки".

## Анализ

### Текущая реализация

1. **API BestBenefits не поддерживает фильтрацию по городу** (строка 106 в `lib/best-benefits.ts`):
   ```typescript
   // if (params.cityId) searchParams.set("city_id", String(params.cityId)); // Отключено - API не фильтрует правильно
   ```

2. **Фильтрация происходит локально** в функции `normalizeResponse` (строки 186-216 в `lib/best-benefits.ts`):
   - Загружаются все скидки
   - Фильтруются только те, у которых `cityIds.includes(params.cityId)`

3. **Фильтрация российских городов** происходит в двух местах:
   - `CityFilter.tsx` (строки 18-23) - фильтрует города для отображения
   - `lib/best-benefits.ts` (строки 300-317) - фильтрует города при нормализации скидок

### Возможные причины проблемы

1. **Некоторые скидки имеют пустой список городов**
   - Такие скидки доступны везде, но не попадают в фильтр по конкретному городу

2. **ID городов не совпадают**
   - В БД BestBenefits могут быть разные ID для одного и того же города
   - Например, "Москва" может иметь ID 1 и ID 77

3. **Скидки с несколькими городами**
   - Скидка может быть доступна в 10 городах
   - При фильтре по одному городу она должна отображаться

4. **Фильтрация только российских городов**
   - Если скидка доступна в СНГ, она отфильтруется
   - Но пользователь может ожидать её увидеть

## Решение

### 1. Улучшенная логика фильтрации

Добавить обработку "глобальных" скидок (без привязки к городу):

```typescript
// В lib/best-benefits.ts, функция normalizeResponse
if (params.cityId) {
  filtered = filtered.filter((discount) => {
    // Если у скидки нет городов - она доступна везде
    if (discount.cities.length === 0) {
      return true;
    }
    
    // Иначе проверяем наличие выбранного города
    const cityIds = discount.cities.map(c => c.id);
    return cityIds.includes(params.cityId!);
  });
}
```

### 2. Улучшенное отображение городов

В `CityFilter.tsx` добавить опцию "Все города":

```typescript
<option value="">Все города (включая скидки без привязки к городу)</option>
```

### 3. Логирование для диагностики

Текущее логирование (строки 192-216 в `lib/best-benefits.ts`) хорошее, но можно добавить:

```typescript
console.log(`[best-benefits] 📍 Global discounts (no cities): ${discounts.filter(d => d.cities.length === 0).length}`);
console.log(`[best-benefits] 📍 City-specific discounts: ${discounts.filter(d => d.cities.length > 0).length}`);
```

### 4. Альтернатива: использовать регион вместо города

Если проблема в разных ID городов, можно:
1. Группировать города по регионам
2. Фильтровать по региону вместо конкретного города
3. Это увеличит количество релевантных скидок

### 5. Проверка данных BestBenefits

Нужно проверить, какие данные приходят от API:

```bash
# На сервере
pm2 logs my-union-pro | grep "best-benefits"
```

Искать строки:
- "Sample discount fields"
- "Discount cities"
- "Filtered out non-Russian city"

## Рекомендации

1. **Включить глобальные скидки** (без привязки к городу) при любом фильтре
2. **Добавить фильтр по региону** вместо города (более гибко)
3. **Показывать количество скидок** для каждого города в фильтре
4. **Кэшировать список городов** для быстрой работы фильтра

## Реализация

Изменения внесены в:
- `lib/best-benefits.ts` - добавлена обработка глобальных скидок
- Логирование улучшено для диагностики

## Тестирование

1. Выберите город в фильтре
2. Проверьте логи: должны быть строки "Before filter" и "After filter"
3. Проверьте, что количество скидок соответствует ожиданиям
4. Если скидок мало - проверьте "Global discounts" в логах

3. Возможно использовать координаты вместо ID городов
