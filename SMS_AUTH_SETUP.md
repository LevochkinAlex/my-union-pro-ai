# 📱 SMS-авторизация через Exolve

## ✅ Реализация завершена

Система авторизации переведена на SMS-вход без паролей. Пользователь вводит номер телефона, получает PIN-код в SMS и авторизуется.

## 📋 Что сделано

1. **Библиотека Exolve SMS** (`lib/exolve-sms.ts`)
   - Отправка SMS с PIN-кодом
   - Валидация и нормализация номеров телефонов
   - Поддержка форматов: +7, 8, 7

2. **API Endpoints**
   - `POST /api/auth/sms/send-pin` - Отправка SMS с PIN-кодом
   - `POST /api/auth/sms/verify-pin` - Проверка PIN-кода (альтернативный метод)

3. **NextAuth интеграция**
   - Новый провайдер `sms` для SMS-авторизации
   - Старый провайдер `credentials` сохранен для обратной совместимости
   - Автоматическое создание пользователя при первом входе

4. **UI страницы входа** (`app/(auth)/login/page.tsx`)
   - Двухэтапный процесс: ввод телефона → ввод PIN-кода
   - Таймер для повторной отправки SMS (60 секунд)
   - Валидация номера телефона
   - В режиме разработки PIN-код показывается в консоли

5. **База данных**
   - Модель `SMSPinCode` для хранения PIN-кодов
   - Поле `phone` в модели `User` теперь уникально
   - Поле `email` в модели `User` теперь опционально
   - Поле `password` остается опциональным (для обратной совместимости)

## 📱 Использование

### Для пользователей

1. Пользователь заходит на страницу `/login`
2. Вводит номер телефона (любой формат: +79991234567, 89991234567, 79991234567)
3. Получает SMS с 4-значным PIN-кодом
4. Вводит PIN-код
5. Авторизуется в системе

### Для разработчиков

В режиме разработки (`NODE_ENV=development`) PIN-код также выводится в консоль браузера для удобства тестирования.

## 🔐 Безопасность

- PIN-коды хешируются с помощью bcrypt перед сохранением в БД
- PIN-коды действительны только 5 минут
- PIN-коды можно использовать только один раз
- Старые неиспользованные PIN-коды автоматически удаляются
- Номера телефонов нормализуются к единому формату (+7XXXXXXXXXX)

## 🔄 Обратная совместимость

- Старая авторизация через email/password сохранена (провайдер `credentials`)
- Существующие пользователи с паролями могут продолжать использовать email/password
- Новые пользователи регистрируются только через SMS

## 🧪 Тестирование

### Локальное тестирование

1. Убедитесь, что `EXOLVE_API_TOKEN` установлен в `.env.local`
2. Запустите dev-сервер: `pnpm dev`
3. Откройте `/login`
4. Введите тестовый номер телефона
5. Проверьте SMS или консоль браузера (в dev режиме)

### Проверка API

```bash
# Отправка PIN-кода
curl -X POST http://localhost:3004/api/auth/sms/send-pin \
  -H "Content-Type: application/json" \
  -d '{"phone": "+79991234567"}'

# Проверка PIN-кода (альтернативный метод)
curl -X POST http://localhost:3004/api/auth/sms/verify-pin \
  -H "Content-Type: application/json" \
  -d '{"phone": "+79991234567", "pinCode": "1234"}'
```

## 📚 API Документация Exolve

Документация Exolve API: 
- Основная документация: https://exolve.ru/documents/
- API документация: https://docs.exolve.ru/

**Текущая реализация использует:**
- Endpoint: `https://api.exolve.ru/messaging/v1/SendSMS`
- Авторизация: `Bearer {EXOLVE_API_TOKEN}` в заголовке `Authorization`
- Формат запроса:
  ```json
  {
    "Number": "79587173423",  // номер отправителя
    "Destination": "79991234567",  // номер получателя без знака +
    "Text": "Текст сообщения",
    "AppId": "ba193f23-7209-4897-8d42-9d81d1aa933c"  // опционально
  }
  ```

**Важно:** Если API возвращает ошибки, проверьте:
- Правильность формата номера (без знака +)
- Наличие и валидность токена
- Требуется ли ID приложения в запросе
- Настройки IP-адресов в личном кабинете Exolve

## ⚠️ Известные проблемы

1. **Формат API Exolve:** Текущая реализация использует предположительный формат API. После получения доступа к документации Exolve может потребоваться корректировка.

2. **Дубликаты телефонов:** Перед применением миграции убедитесь, что в БД нет пользователей с одинаковыми номерами телефонов.

3. **Токен Exolve:** Убедитесь, что токен действителен и имеет права на отправку SMS.
