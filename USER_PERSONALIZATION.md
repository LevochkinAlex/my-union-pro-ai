# Персонализация и контекст бота

Обновлено: 28 ноября 2024

## Проблема
Бот не помнил контекст пользователя и общался так, будто видит его впервые, даже после того как пользователь заполнил анкету и подал заявление.

## Решение

### 1. Информация о пользователе в системном промпте

Бот теперь **автоматически получает** всю информацию о пользователе при каждом сообщении:

```typescript
// app/api/chat/route.ts - строки 161-202

// Основная информация
- Имя (ФИО)
- Организация
- Должность
- Профессия
- Город

// Дополнительная информация (если заполнена)
- Занятость (работа/учеба/пенсия)
- Семейное положение
- Информация о супруге
- Дети (имена и даты рождения)
- Хобби
- О себе
```

### 2. Инструкции для бота

Бот получает явные инструкции:

```
⚠️ КРИТИЧЕСКИ ВАЖНО:
- ОБЯЗАТЕЛЬНО обращайся к пользователю по имени (не говори "пользователь")
- Используй информацию о его организации, должности, профессии в ответах
- Если знаешь про детей/семью/хобби - упоминай это естественно в беседе
- Веди себя как помощник, который УЖЕ ЗНАЕТ пользователя
- НЕ спрашивай заново то, что уже знаешь о пользователе
- Будь дружелюбным и персональным, а не формальным ботом
```

### 3. Контекст для всех типов сессий

Информация о пользователе передается и в **STATEMENT** (заявления), и в **APPEAL** (обращения):

```typescript
// Для всех типов сессий
const user = await prisma.user.findUnique({
  where: { id: session.user.id },
});

// Передается в системный промпт
const systemPrompt = await buildSystemPrompt(
  bot, 
  relevantChunks, 
  chatSession.type, 
  user, // ← Всегда передаем
  hasGeneratedDocuments
);
```

## Блокировка обращений без документов

### Проблема
Пользователи могли создавать обращения (APPEAL) до того, как заполнили и загрузили заявления.

### Решение

#### 1. Серверная проверка (API)

```typescript
// app/api/chat/route.ts - строки 762-783

if (chatSession.type === "APPEAL") {
  // Проверяем, загружены ли подписанные документы (статус SIGNED или выше)
  const uploadedDocuments = await prisma.document.findMany({
    where: {
      userId: session.user.id,
      type: {
        in: ["MEMBERSHIP_APPLICATION", "CONTRIBUTION_APPLICATION"],
      },
      status: {
        in: ["SIGNED", "PENDING", "APPROVED"],
      },
      filePath: {
        not: null, // Убеждаемся что файл реально загружен
      },
    },
  });
  
  if (uploadedDocuments.length < 2) {
    return NextResponse.json(
      { 
        error: "Для создания обращений необходимо сначала заполнить и загрузить подписанные заявления...",
        requiresDocuments: true,
      },
      { status: 403 }
    );
  }
}
```

#### 2. UI блокировка (Фронтенд)

В `components/dashboard/ChatMenu.tsx`:

- **Проверка статуса документов** при загрузке меню
- **Disabled кнопка "Новый чат"** если документы не загружены
- **Тултип** с объяснением почему кнопка заблокирована
- **Иконка замка** 🔒 на заблокированной кнопке

```typescript
// Проверка при загрузке
const uploadedDocs = data.documents?.filter(
  (doc: any) => 
    (doc.type === "MEMBERSHIP_APPLICATION" || doc.type === "CONTRIBUTION_APPLICATION") &&
    (doc.status === "SIGNED" || doc.status === "PENDING" || doc.status === "APPROVED") &&
    doc.filePath
) || [];
setDocumentsUploaded(uploadedDocs.length >= 2);

// Кнопка с блокировкой
<button
  onClick={handleNewAppeal}
  disabled={!documentsUploaded}
  title={!documentsUploaded ? "Сначала загрузите подписанные заявления..." : "..."}
>
```

## Новый флоу онбординга

1. **Приветствие** → "Я уникальный AI-бот профсоюза..."
2. **Кнопка "Заполнить анкету"** → Открывает модальное окно
3. **Модальная форма** → Заполнение всех полей с валидацией
4. **Генерация документов** → Автоматически после заполнения
5. **Загрузка подписанных документов** → Пользователь скачивает, подписывает, загружает
6. **✅ Разблокировка обращений** → После загрузки обоих документов
7. **Персонализированное общение** → Бот знает всё о пользователе

1. Создайте нового пользователя
2. Войдите в систему
3. Откройте "Мой бот"
4. Попробуйте нажать "Новый чат" → должна быть заблокирована 🔒
5. Заполните анкету через модальное окно
6. Загрузите подписанные документы

## Важные замечания

- **Никогда** не собирайте данные через чат - только через модальную форму
- **Всегда** проверяйте статус документов перед созданием APPEAL
- **Всегда** передавайте информацию о пользователе в системный промпт
- **Естественно** упоминайте детали о пользователе в беседе
