# Конфигурация окружения (ENV) для экспертной проверки экземпляра ПО

**Программное обеспечение:** МойСоюз (myunion.pro)  
**Правообладатель:** ООО "ЯППИКС"  
**Назначение документа:** описание переменных окружения и правил подготовки `.env.local` для запуска тестового экземпляра.

---

## 1. Общие правила

1. Для запуска используется файл `.env.local`, сформированный на основе `.env.example`.
2. В документацию и передаваемые материалы включаются только шаблонные значения.
3. Реальные секреты (пароли, токены, ключи) в документы и открытые каналы не передаются.
4. Для экспертной проверки допускается использование тестовых ключей/учетных данных.

---

## 2. Минимально необходимые переменные (обязательные)

Ниже приведен минимальный набор для запуска экземпляра:

```env
# URL PostgreSQL (пример формата)
DATABASE_URL="postgresql://USER:PASSWORD@HOST:5432/DB_NAME"

# Базовый URL приложения
NEXTAUTH_URL="http://localhost:3004"

# Криптографический секрет NextAuth
NEXTAUTH_SECRET="REPLACE_WITH_SECURE_RANDOM_STRING"
```

Без указанных переменных полноценная работа экземпляра невозможна.

---

## 3. Рекомендуемые переменные (по сценарию проверки)

### 3.1. Почтовые уведомления

```env
SMTP_HOST=""
SMTP_PORT=""
SMTP_USER=""
SMTP_PASSWORD=""
SMTP_FROM=""
```

Нужны, если в ходе проверки тестируются email-уведомления, восстановление доступа, сервисные письма.

### 3.2. Публичный URL и CDN

```env
NEXT_PUBLIC_APP_URL="https://myunion.pro"
NEXT_PUBLIC_CDN_URL=""
```

Используются для формирования абсолютных ссылок и выдачи файлов.

### 3.3. Real-time (чат/события)

```env
NEXT_PUBLIC_SOCKET_URL="http://localhost:3005"
REDIS_URL="redis://localhost:6379"
```

Нужны для сценариев real-time обмена сообщениями.

### 3.4. Интеграции авторизации и внешние API (опционально)

Примеры (заполняются только при проверке соответствующей функции):

```env
VK_ID_CLIENT_ID=""
MAX_BOT_TOKEN=""
NEXT_PUBLIC_MAX_BOT_USERNAME=""
YANDEX_AI_STUDIO_API_KEY=""
YANDEX_CLOUD_FOLDER_ID=""
DADATA_API_KEY=""
DADATA_SECRET_KEY=""
```

---

## 4. Порядок подготовки env для экспертизы

1. Скопировать шаблон:

```bash
cp .env.example .env.local
```

2. Заполнить обязательные параметры (`DATABASE_URL`, `NEXTAUTH_URL`, `NEXTAUTH_SECRET`).
3. Заполнить опциональные параметры в зависимости от сценария проверки.
4. Проверить корректность без вывода секретов в консоль.

---

## 5. Контрольный список перед запуском

- [ ] `.env.local` создан и находится в корне проекта
- [ ] заполнен `DATABASE_URL`
- [ ] заполнены `NEXTAUTH_URL` и `NEXTAUTH_SECRET`
- [ ] применены миграции БД (`npx prisma migrate deploy`)
- [ ] сборка проходит (`pnpm build`)
- [ ] приложение запускается (`pnpm start`)

---

## 6. Требования безопасности к env

- Файлы `.env*` с реальными секретами не размещаются в публичном доступе.
- Нельзя передавать секреты через открытые чаты и email без шифрования.
- Доступ к env-файлам должен быть ограничен только ответственным сотрудникам.
- При компрометации ключа/пароля необходимо немедленно заменить секрет и обновить конфигурацию.

---

## 7. Примечание для экспертной проверки

Для целей экспертизы допускается:
- использование тестовых SMTP/API ключей;
- отключение части внешних интеграций, не влияющих на базовый запуск экземпляра;
- предоставление эксперту отдельного "санитизированного" env-шаблона без секретов.
