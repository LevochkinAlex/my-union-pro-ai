# Процесс деплоя

## Инфраструктура

- **Сервер приложения (деплой):** 194.87.49.210 (VDS), приложение в `/opt/my-union-pro`, PM2.
- **База данных:** VK Cloud PostgreSQL — хост 83.166.237.161, база `myunion_db`. Локальная разработка и прод подключаются к одной БД (DATABASE_URL в `.env.local` и на сервере указывает на VK Cloud).

## Автоматические тесты перед деплоем

Перед каждым деплоем автоматически запускается тестовый скрипт для проверки API обращений:

```bash
pnpm dotenv -e .env.local -- node scripts/test-tickets-api.mjs
```

### Что проверяет тест:

1. **Доступность API endpoint** `/api/tickets`
2. **Структура ответа** - проверка обратной совместимости
3. **Prisma схема** - проверка наличия новых полей (responseDeadline, isOverdue и др.)

### Результат теста:

- ✅ **Успех**: Тест проходит, деплой продолжается
- ❌ **Ошибка**: Тест не проходит, деплой прерывается

### Скрипты деплоя с тестами:

- `commit-and-deploy.sh` - коммит, пуш и деплой с тестами
- `deploy.sh` - деплой с тестами
- `deploy-now.sh` - быстрый деплой с тестами
- `scripts/deploy-production.sh` - продакшн деплой с тестами

### Ручной запуск теста:

```bash
pnpm dotenv -e .env.local -- node scripts/test-tickets-api.mjs
```

### Примечания:

- Тест не требует авторизации для базовой проверки
- Отсутствие новых полей в Prisma на локальной машине - не критично (миграция применится на сервере)
- Главное - API endpoint должен быть доступен и отвечать корректно
