# Удаление пользователя из системы

## Какие проблемы возникнут при простом удалении

Если в супер-админке просто вызвать удаление пользователя (без предварительной зачистки), **БД выдаст ошибку внешнего ключа (FK)**: часть таблиц ссылается на `User.id` без `ON DELETE CASCADE` / `ON DELETE SET NULL`, поэтому удаление пользователя запрещено.

### Связи без onDelete (до правок)

| Модель | Поле | Проблема при удалении User |
|--------|------|----------------------------|
| **ChatMessage** | senderId | Сообщения в чатах — FK не даст удалить пользователя |
| **ChatMessageReaction** | userId | Реакции на сообщения |
| **ChatMessageRead** | userId | Отметки «прочитано» |
| **DocumentTemplate** | createdByUserId, updatedByUserId | Шаблоны документов |
| **Meeting** | createdById | Заседания (создатель) — поле обязательное |
| **MeetingAgendaItem** | speakerId, coSpeakerId | Докладчик/содокладчик в повестке |
| **MeetingAgendaVote** | userId | Голоса по пунктам повестки |
| **KnowledgeDocument** | uploadedByUserId | Документы в базе знаний |
| **SystemSetting** | updatedByUserId | Кто последний менял настройку |

Остальные связи с User уже имеют `onDelete: Cascade` или `onDelete: SetNull` (документы, обращения, участники чатов, уведомления и т.д.) — они либо удалятся вместе с пользователем, либо обнулятся.

## Цель: полное удаление аккаунта

Требуется, чтобы при удалении из системы:

- аккаунт был **полностью удалён** (запись User и все зависимые данные);
- пользователь **исчез из чатов** (его сообщения и участие зачищены);
- **документы и обращения** пользователя удалены (уже обеспечивается Cascade);
- в переписках и профгруппе не осталось следов этого пользователя.

## Решение

1. **Схема (Prisma)**  
   Менять внешние ключи на User на `ON DELETE CASCADE` **не обязательно**: всю зачистку делает код в `lib/delete-user.ts` перед удалением пользователя. Единственное изменение в схеме — поле `Meeting.createdById` сделано опциональным (`String?`), чтобы при удалении пользователя можно было обнулить создателя заседания. Остальные FK оставлены без изменений.

2. **Логика удаления**  
   В коде выполняется полное удаление пользователя в одной транзакции:
   - удаляются **реакции** и **прочитано** пользователя в чатах (ChatMessageReaction, ChatMessageRead);
   - удаляются все **сообщения** пользователя в чатах (ChatMessage где senderId = userId);
   - обнуляются ссылки на пользователя (создатель чата, пригласивший, шаблоны, заседания, пункты повестки, голоса, база знаний, настройки) — всё в коде, без изменения FK в БД;
   - затем выполняется **удаление User** — по каскаду удаляются его документы, обращения, участникство в чатах, уведомления и прочие связи с Cascade.

3. **API и UI**  
   - Удаление: **DELETE** `/api/admin/users/[id]` (только супер-админ).  
   - На странице пользователя в супер-админке кнопка **«Удалить»** с подтверждением использует эту логику.

В результате при удалении пользователя из супер-админки аккаунт полностью исчезает из системы: из чатов, из профгруппы, из всех переписок; его документы, обращения и чаты зачищаются.
