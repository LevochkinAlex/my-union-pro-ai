# Руководство по тестированию

## Обязательные проверки перед коммитом

### 1. TypeScript проверка
```bash
npm run type-check
```
Проверяет, что нет ошибок компиляции TypeScript.

### 2. Линтер
```bash
npm run lint
```
Проверяет код на соответствие стандартам.

### 3. Тесты API
```bash
npm run test:api
```
Проверяет работу API обращений.

### 4. Комплексный тест создания обращения
```bash
npm run test:ticket-flow
```
Проверяет весь процесс создания обращения, включая создание сообщения в чате.

## Проверка перед деплоем

### Полная проверка
```bash
npm run pre-deploy
```

Проверяет:
- ✅ TypeScript компиляция
- ✅ Prisma схема
- ✅ Подключение к БД
- ✅ Критические API endpoints
- ✅ Структура БД для обращений
- ✅ Обращения с чатами и сообщениями

## Автоматические проверки

### Pre-commit hook
При каждом коммите автоматически запускаются:
- TypeScript проверка
- Линтер

Если проверки не пройдены, коммит будет отклонен.

## Исправление проблем

### Обращения без начальных сообщений
Если обнаружены обращения без сообщений в чате:
```bash
node scripts/fix-missing-appeal-messages.mjs
```

### Проблемы с миграциями
Если новые поля не доступны:
```bash
npx prisma migrate deploy
npx prisma generate
```

## Чеклист перед деплоем

- [ ] `npm run type-check` - нет ошибок
- [ ] `npm run lint` - нет критических ошибок
- [ ] `npm run test:api` - API работает
- [ ] `npm run test:ticket-flow` - создание обращения работает
- [ ] `npm run pre-deploy` - все проверки пройдены
- [ ] Миграции применены на проде
- [ ] Логи проверены на наличие ошибок

## Важные моменты

1. **Всегда тестируйте перед коммитом** - используйте pre-commit hook
2. **Проверяйте обратную совместимость** - код должен работать до и после миграции
3. **Проверяйте реальные сценарии** - не только happy path
4. **Логируйте ошибки детально** - для быстрой диагностики на проде
