**Назначение документа:** регламент эксплуатации тестового экземпляра ПО для экспертной проверки.

---

## 1. Назначение и состав экземпляра

Экземпляр ПО предоставляется для проверки функциональности web-платформы "МойСоюз" и включает:
- серверную часть приложения (Next.js/Node.js);
- клиентскую web-часть;
- реляционную базу данных PostgreSQL;
- подсистему real-time обмена сообщениями (Socket-сервер);
- конфигурацию окружения;
- скрипты сборки, запуска, миграций и обновления.

---

## 2. Минимальные требования к среде эксплуатации

- ОС: Linux (рекомендуется Ubuntu 22.04/24.04 LTS)
- CPU: от 4 vCPU
- RAM: от 8 GB
- Диск: от 40 GB SSD
- Обязательное ПО:
  - Node.js LTS (20+)
  - pnpm (10+)
  - PostgreSQL (15+)
  - PM2
  - Nginx (для reverse proxy/HTTPS)
  - Redis (для кеша/очередей, если включено)

## 3. Подготовка и установка экземпляра

### 3.1. Получение кода

1. Получить исходный код из репозитория правообладателя.
2. Разместить проект в рабочем каталоге (например, `/opt/my-union-pro`).

### 3.2. Установка зависимостей

```bash
pnpm install
```

### 3.3. Настройка конфигурации

1. Создать файл `.env.local` на основе `.env.example`.
2. Заполнить обязательные параметры (см. документ `ENV_FOR_EXPERT_REVIEW.md`).
3. Убедиться, что указаны корректные значения для:
   - `DATABASE_URL`
   - `NEXTAUTH_URL`
   - `NEXTAUTH_SECRET`
   - SMTP/SMS/внешних интеграций (при необходимости проверки этих функций).

### 3.4. Подготовка БД

```bash
npx prisma migrate deploy
```

### 3.5. Сборка и запуск

```bash
pnpm build
pnpm start
```

Для промышленного режима рекомендуется запуск под PM2:

```bash
pm2 start "pnpm start" --name my-union-pro
pm2 start "pnpm socket" --name my-union-socket
pm2 save
```

## 4. Базовая эксплуатация

### 4.1. Проверка работоспособности после запуска

1. Открыть URL экземпляра в браузере.
2. Проверить страницу входа и авторизацию тестового пользователя.
3. Проверить ключевые разделы:
   - профиль пользователя;
   - документы;
   - обращения;
   - чаты;
   - отчеты/аналитику.

### 4.2. Основные команды обслуживания

```bash
# проверка процессов
pm2 list

# логи приложения
pm2 logs my-union-pro --lines 100

# логи сокет-сервера
pm2 logs my-union-socket --lines 100

# перезапуск
pm2 restart my-union-pro
pm2 restart my-union-socket
```

### 4.3. Обновление экземпляра

```bash
git pull origin main
pnpm install
npx prisma migrate deploy
pnpm build
pm2 restart my-union-pro
pm2 restart my-union-socket
```

## 5. Мониторинг и диагностика

В процессе эксплуатации выполняются:
- контроль доступности web-приложения;
- контроль состояния PM2-процессов;
- анализ логов приложения;
- контроль выполнения миграций БД;
- контроль корректной работы интеграций (email/SMS/внешние API).

При возникновении неисправности используется регламент:
1. фиксация инцидента;
2. сбор логов и диагностика;
3. локализация причины (код, данные, окружение);
4. выпуск исправления;
5. повторная проверка и ввод в эксплуатацию.

---

## 6. Резервное копирование и восстановление

В эксплуатационном контуре рекомендуется:
- регулярное резервное копирование базы данных PostgreSQL;
- резервирование критичных конфигурационных файлов (без разглашения секретов);
- проверка процедуры восстановления на тестовом контуре.

Рекомендуемый минимум:
- ежедневный бэкап БД;
- хранение не менее 7-30 последних копий (по внутреннему регламенту);
- периодическая проверка восстановления.

---

## 7. Требования по информационной безопасности при эксплуатации

- доступ к серверу и БД предоставляется только уполномоченным сотрудникам;
- секреты (ключи, токены, пароли) хранятся только в защищенных env-файлах;
- запрещено публиковать `.env.local`, дампы БД и закрытые ключи в открытом доступе;
- передача данных выполняется по защищенному каналу HTTPS;
- применяются разграничение прав доступа и аудит действий.
