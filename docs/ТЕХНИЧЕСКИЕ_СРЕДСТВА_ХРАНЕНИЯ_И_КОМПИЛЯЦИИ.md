## 1. Технические средства хранения исходного текста программного обеспечения

### 1.1. Система контроля версий и репозиторий

Исходный текст программного обеспечения хранится в системе контроля версий **Git**. Основной репозиторий размещён на платформе **GitHub** ([github.com/myunion-pro](https://github.com/myunion-pro)); адрес репозитория правообладателя указывается в заявлении (например, `github.com/myunion-pro/my-union-pro-ai` или актуальный на дату подачи). Используется распределённое хранение: локальные копии репозитория на рабочих станциях разработки и централизованная копия на GitHub.

**Характеристики хранения исходного кода:**
- **Формат файлов:** текстовые файлы в кодировке UTF-8.
- **Языки программирования и разметки:** TypeScript (.ts, .tsx), JavaScript (.js, .mjs), CSS, HTML, JSON, Prisma Schema (.prisma), shell-скрипты и др.
- **Структура каталогов:** корневой каталог проекта; подкаталоги `app/`, `components/`, `lib/`, `server/`, `scripts/`, `prisma/`, `public/` и др. содержат модули исходного кода, конфигурации и ресурсы.
- **Версионирование:** каждая значимая версия и набор изменений фиксируются коммитами Git с уникальным идентификатором (SHA). Ветка по умолчанию для поставки — `main`.

### 1.2. Локальное и серверное хранение исходного кода

- **На рабочих станциях разработки:** исходный код хранится в локальной файловой системе в каталоге клонированного репозитория (например, на носителях разработчиков).
- **На сервере сборки и эксплуатации (VDS):** копия репозитория размещается в каталоге развёртывания приложения (например, `/opt/my-union-pro`), обновляется командой `git pull` в рамках процесса развёртывания. Исходные файлы сохраняются на диске сервера в том же виде, что и в репозитории.

Исходный текст не хранится в скомпилированном или обфусцированном виде; доступ к репозиторию и каталогам с исходным кодом ограничен правообладателем и уполномоченными лицами.

## 2. Технические средства хранения объектного кода (результатов компиляции/сборки)

Под объектным кодом в контексте данного ПО понимаются результаты компиляции и сборки: скомпилированный JavaScript, собранные бандлы и артефакты, используемые для запуска приложения в среде выполнения.

### 2.1. Артефакты сборки веб-приложения (Next.js)

- **Каталог:** `.next/` в корне проекта.
- **Содержимое:** результаты сборки фреймворка Next.js (внутренняя структура каталогов: `cache/`, `server/`, `static/`, файлы маршрутов, скомпилированные компоненты, статические страницы и т.п.). Код представлен в виде JavaScript (и при необходимости иные форматы), пригодный для выполнения в среде Node.js и в браузере.
- **Получение:** формируется командой `pnpm build` (которая запускает `next build`) на сервере сборки или при развёртывании. Каталог `.next/` не входит в репозиторий Git (указан в `.gitignore`) и создаётся при каждой сборке.

### 2.2. Артефакты сборки серверных компонентов (Socket-сервер и др.)

- **Каталог:** `dist/` (при использовании отдельной сборки, например для socket-сервера).
- **Содержимое:** скомпилированные и собранные в один или несколько файлов модули (например, `dist/server/socket-server.js`), пригодные для запуска в Node.js.
- **Получение:** формируется инструментом сборки (например, esbuild) по соответствующей команде (например, `pnpm socket:build`). Каталог `dist/` может быть исключён из репозитория и создаётся при сборке.

### 2.3. Сгенерированный клиент БД (Prisma)

- **Расположение:** подкаталог внутри `node_modules/` (например, `node_modules/.pnpm/.../node_modules/@prisma/client/`), генерируется в рамках проекта.
- **Содержимое:** сгенерированный на основе схемы Prisma клиент для доступа к базе данных (JavaScript/TypeScript-код).
- **Получение:** команда `pnpm prisma generate` (или `pnpm prisma:generate`). Данный код не хранится в репозитории в сгенерированном виде; хранится только исходная схема `prisma/schema.prisma`.

### 2.4. Место хранения при эксплуатации

Объектный код (каталоги `.next/`, при необходимости `dist/`, а также установленные зависимости в `node_modules/`) хранится на сервере эксплуатации (VDS) в каталоге развёртывания приложения. Запуск приложения выполняется процессами Node.js (в т.ч. под управлением менеджера процессов PM2), которые используют указанные артефакты.

## 3. Технические средства компиляции исходного текста в объектный код

### 3.1. Общая схема процесса сборки

Сборка (компиляция и объединение исходного кода в пригодный для выполнения вид) выполняется на сервере или на рабочих станциях с установленным окружением (Node.js, менеджер пакетов pnpm). Основные этапы:

1. Клонирование или обновление репозитория с исходным кодом (`git pull`).
2. Установка зависимостей: `pnpm install`.
3. Генерация клиента Prisma: `pnpm prisma generate`.
4. Запуск сборки веб-приложения: `pnpm build` → `next build`.
5. При необходимости — отдельная сборка серверных модулей (например, `pnpm socket:build`).

### 3.2. Используемое программное обеспечение и инструменты компиляции/сборки

| Назначение | Программный продукт / инструмент | Версия (ориентировочно) | Краткое описание |
|-----------|----------------------------------|---------------------------|------------------|
| Среда выполнения | Node.js | 20.x / 22.x (LTS) | Среда выполнения JavaScript на стороне сервера; используется для запуска сборки и работы приложения. |
| Менеджер пакетов | pnpm | 10.x | Установка зависимостей и выполнение скриптов сборки (build, prisma generate и др.). |
| Сборка веб-приложения | Next.js (включая Turbopack при сборке) | 16.x | Фреймворк сборки и выполнения: компиляция TypeScript/JSX, бандлинг, оптимизация, генерация статических и серверных маршрутов. Исходный код (TypeScript/React) преобразуется в выполняемый JavaScript. |
| Проверка типов (без генерации файлов) | TypeScript (tsc) | 5.x | Команда `tsc --noEmit` используется для проверки типов; в конфигурации проекта компиляция с выдачей файлов отключена (`noEmit: true`), генерацию выполняет Next.js. |
| Сборка отдельного серверного модуля | esbuild | 0.27.x | Компиляция и бандлинг TypeScript в один JavaScript-файл (например, socket-server.ts → dist/server/socket-server.js). |
| Генерация кода доступа к БД | Prisma (prisma generate) | 6.x | По схеме `prisma/schema.prisma` генерируется клиент БД (исходный текст схемы — входные данные; результат — код в node_modules). |
| Выполнение скриптов на TypeScript без предварительной компиляции | tsx | — | Запуск .ts-скриптов в режиме разработки (интерпретация/трансформация на лету). |

### 3.3. Конфигурация компиляции и сборки

- **TypeScript:** файл `tsconfig.json` задаёт целевой стандарт (ES2017), модульную систему, пути импорта, использование JSX и интеграцию с Next.js. Генерация выходных файлов отключена (`noEmit: true`), компиляция в итоговый код выполняется сборщиком Next.js.
- **Next.js:** конфигурация в `next.config.ts` (или аналог) определяет параметры сборки, окружения, маршруты и постобработку (при наличии).
- **Prisma:** файл `prisma/schema.prisma` описывает модель данных; команда `prisma generate` создаёт клиент на основе этой схемы.

### 3.4. Результат компиляции/сборки

В результате выполнения указанных команд исходный текст (TypeScript, JSX, CSS и др.) преобразуется в объектный код в виде:
- JavaScript-файлов и бандлов в каталоге `.next/`, исполняемых в Node.js и в браузере;
- при необходимости — отдельных скомпилированных модулей в каталоге `dist/`;
- сгенерированного клиента Prisma в `node_modules`.

Указанный объектный код используется для эксплуатации программного обеспечения без повторной компиляции до следующего обновления исходного кода и повторного запуска сборки.

## 4. Краткое резюме

- **Хранение исходного текста:** система контроля версий Git, репозиторий на GitHub (организация myunion-pro), локальные и серверные копии в виде текстовых файлов (TypeScript, JavaScript, конфигурации и т.д.) в структуре каталогов проекта.
- **Хранение объектного кода:** каталоги `.next/` и при необходимости `dist/`, сгенерированный Prisma Client в `node_modules/`, на диске сервера эксплуатации (и при необходимости на сервере сборки).
- **Компиляция/сборка:** Node.js, pnpm, Next.js (Turbopack), TypeScript (tsc), esbuild, Prisma — по конфигурации проекта и скриптам в `package.json`. Исходный текст компилируется и собирается в выполняемый объектный код при каждой сборке перед развёртыванием.
