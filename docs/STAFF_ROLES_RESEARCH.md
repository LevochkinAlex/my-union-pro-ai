# Исследование: роли сотрудников и интерфейс

## Роли в системе (dashboard/staff)

Создаются в `prisma/seed-staff-roles.ts` и в интерфейсе **Сотрудники** (`/dashboard/staff`):

| Роль | Описание | Ключевые права |
|------|----------|----------------|
| **Заместитель председателя** | Почти полный доступ, кроме управления сотрудниками | documents, discounts, members (view+edit), appeals, chats, news, reports, settings_view, **staff_view** (без staff_manage), без members_manage |
| **Бухгалтер** | Документы, отчёты, члены | documents_view/create/edit, members_view, chats, news_view, reports_view/create, **без** discounts, appeals, staff, settings |
| **Секретарь** | Документы, обращения, новости | documents, members_view, appeals_view/respond, chats, news_view/create, reports_view, **staff_view** |
| **Специалист по работе с членами** | Члены, скидки, обращения | members_view/edit, discounts_view/manage, appeals_view/respond, documents_view только, **без** reports, news_create, staff |
| **Специалист по информационной работе** | Новости и чаты | news_view/create/manage, chats_view/participate/create, documents_view, discounts_view, members_view, **без** reports, appeals |
| **Член профкома** | Выборный орган, участие в заседаниях | documents_view, discounts_view, members_view, appeals_view, chats, news_view, **без** создания документов/отчётов, без staff |

Права задаются в `StaffRole.permissions` (JSON). Проверка — в `lib/staff-permissions.ts` (`checkUserPermissions`, `requirePermission`).

---

## Соответствие интерфейса и доступов

### 1. Меню дашборда (layout) — **не соответствует**

**Как устроено сейчас:** в `app/dashboard/layout.tsx` меню строится только по **viewMode**:

- `viewMode === "PPO_HEAD"` → полное меню председателя (Документы, Обращения, Новости, Профсеть, Чаты, Скидки, Члены профсоюза, Отчётность, Сотрудники, Настройки и т.д.).
- `viewMode === "MPO_HEAD"` / `"RPO_HEAD"` → меню руководителя МПО/РПО.
- Иначе → меню **обычного члена профсоюза** (Документы, Обращения, Новости, Чат, Уведомления, Профсеть, Скидки, Профиль, Настройки).

**Проблема:** сотрудники с ролями (Бухгалтер, Секретарь и т.д.) не являются председателями: у них `viewMode === "MEMBER"`. Им показывается **то же меню, что и рядовому члену**. Они не видят:

- Документы (заседания, повестки, протоколы)
- Обращения в режиме председателя
- Члены профсоюза
- Чаты ППО
- Отчётность
- Раздел «Сотрудники»
- Настройки организации

То есть **права из ролей в меню не учитываются** — сотрудники не могут попасть в нужные разделы, даже если у них есть права в API.

### 2. API (ppo-head) — **соответствует**

В `app/api/ppo-head/*` доступ проверяется так:

- Либо пользователь председатель (`getPPOHead`), либо
- Вызов `checkUserPermissions(userId, permission)` — для сотрудников берётся `OrganizationStaff` + `StaffRole.permissions`.

Примеры:

- `documents/route.ts` — `documents_view` / `documents_create`
- `reports/[id]/route.ts` — `reports_view` / `reports_create`
- `staff/route.ts` — председатель или `staff_view` у роли

То есть **ограничения по ролям на бэкенде работают**. Проблема только в том, что сотрудники не получают меню, чтобы дойти до этих разделов.

### 3. Страницы (клиент)

- **Документы (meetings):** загрузка через API; при отсутствии прав API вернёт 403 — поведение корректно, но ссылка на раздел у сотрудников в текущем меню отсутствует.
- **Обращения:** в `appeals/page.tsx` режим «председатель» включается по `session?.user?.viewMode === "PPO_HEAD"` (и аналогично). Сотрудники с `viewMode === "MEMBER"` не попадают в интерфейс председателя, даже при наличии `appeals_view`/`appeals_respond`.

Итого: **доступы и ограничения в API соответствуют ролям; меню и часть страниц не дают сотрудникам интерфейс под их права.**

## Рекомендации

1. **Меню дашборда**  
   В layout при `viewMode === "MEMBER"` дополнительно проверять: пользователь — активный сотрудник ППО (`OrganizationStaff` + роль). Если да — показывать **меню интерфейса ППО**, но **отфильтрованное по правам** роли:
   - Документы — `documents_view`
   - Обращения — `appeals_view`
   - Новости — `news_view`
   - Профсеть — например, `members_view` или отдельное право
   - Чаты — `chats_view`
   - Скидки — `discounts_view`
   - Члены профсоюза — `members_view`
   - Отчётность — `reports_view`
   - Сотрудники — `staff_view`
   - Настройки — `settings_view` или `settings_manage`

2. **Режим отображения для сотрудников**  
   Либо в layout при наличии активной должности в ППО считать режим «как ППО» и строить меню по правам (как выше), либо ввести отдельный `viewMode` для сотрудников (если по продукту нужно явно различать «председатель» и «сотрудник» в UI).

3. **Страница обращений**  
   Учитывать не только `viewMode === "PPO_HEAD"`, но и факт доступа к организации ППО с правом `appeals_view` (через `checkUserPermissions` или аналог), чтобы показывать интерфейс обращений ППО и сотрудникам с нужной ролью.

После внедрения этих изменений интерфейс сотрудников будет соответствовать назначенным ролям и правам в системе.
