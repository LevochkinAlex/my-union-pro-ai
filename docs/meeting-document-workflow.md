# Документооборот заседаний - API Документация

## Обзор

Система документооборота для заседаний профкома реализует следующий workflow согласно алгоритму:

1. **DRAFT (Черновик)** - Документ создан
2. **PENDING_APPROVAL (На согласовании)** - Документ отправлен участникам
3. **COMPLETED (Утверждено)** - Документ утвержден председателем

## API Endpoints

### 1. Отправка документа на согласование

**POST** `/api/ppo-head/meetings/[id]/documents/[documentId]/send-for-approval`

Отправляет документ (повестку или протокол) на согласование участникам заседания.

**Требования:**
- Пользователь должен быть председателем организации
- Документ должен быть в статусе `DRAFT`
- Документ должен быть связан с заседанием
- В заседании должны быть участники (кроме председателя)

**Ответ:**
```json
{
  "document": {
    "id": "...",
    "status": "PENDING_APPROVAL",
    "approvals": [...]
  },
  "message": "Документ отправлен на согласование N участникам"
}
```

**Ошибки:**
- `400` - Документ уже отправлен или не связан с заседанием
- `401` - Не авторизован
- `403` - Нет доступа
- `404` - Заседание или документ не найдены

---

### 2. Согласование документа участником

**POST** `/api/ppo-head/meetings/[id]/documents/[documentId]/approve`

Участник заседания согласовывает документ.

**Требования:**
- Пользователь должен быть участником заседания (не председателем)
- Документ должен быть в статусе `PENDING_APPROVAL`
- Должна существовать запись согласования для пользователя

**Тело запроса:**
```json
{
  "comment": "Согласовано" // опционально
}
```

**Ответ:**
```json
{
  "message": "Документ согласован",
  "allApproved": false,
  "pendingCount": 2,
  "totalApprovals": 5,
  "approvedCount": 3
}
```

**Ошибки:**
- `400` - Документ не на согласовании или уже согласован
- `401` - Не авторизован
- `403` - Пользователь не является участником
- `404` - Документ, заседание или согласование не найдены

---

### 3. Финальное утверждение документа председателем

**POST** `/api/ppo-head/meetings/[id]/documents/[documentId]/final-approve`

Председатель утверждает документ после согласования всеми участниками.

**Требования:**
- Пользователь должен быть председателем заседания
- Документ должен быть в статусе `PENDING_APPROVAL`
- Все участники должны согласовать документ
- Документ должен быть связан с заседанием

**Тело запроса:**
```json
{
  "comment": "Утверждено" // опционально
}
```

**Ответ:**
```json
{
  "document": {
    "id": "...",
    "status": "COMPLETED",
    "approvedById": "...",
    "approvedAt": "..."
  },
  "message": "Документ успешно утвержден"
}
```

**Ошибки:**
- `400` - Документ не на согласовании или не все участники согласовали
- `401` - Не авторизован
- `403` - Пользователь не является председателем
- `404` - Заседание или документ не найдены

## Workflow

### Повестка дня

1. Создание заседания с повесткой
2. Генерация документа "Повестка дня" → статус `DRAFT`
3. Отправка на согласование → статус `PENDING_APPROVAL`
4. Участники согласовывают документ
5. Председатель утверждает → статус `COMPLETED`
6. Отправка утвержденной повестки участникам

### Протокол

1. Проведение заседания
2. Заполнение протокола
3. Генерация документа "Протокол" → статус `DRAFT`
4. Отправка на согласование → статус `PENDING_APPROVAL`
5. Участники согласовывают документ
6. Председатель утверждает → статус `COMPLETED`
7. Отправка утвержденного протокола участникам

## Безопасность

- Все endpoints требуют аутентификации
- Проверка прав доступа на уровне организации
- Проверка роли пользователя (председатель/участник)
- Валидация связи документа с заседанием
- Проверка статусов документов перед операциями
