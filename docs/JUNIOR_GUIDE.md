## 1. Глоссарий терминов

### Базовые термины IT

| Термин | Что это значит |
|--------|---------------|
| **Фронтенд (Frontend)** | То, что видит пользователь: кнопки, формы, страницы. Код, который работает в браузере. |
| **Бэкенд (Backend)** | Серверная часть: обработка данных, авторизация, работа с базой данных. Пользователь его не видит. |
| **Фуллстек (Fullstack)** | Разработчик, который делает и фронт, и бэк. Наш проект — фуллстек на Next.js. |
| **API** | «Контракт» между фронтом и бэком. Фронт отправляет запрос (например, «дай список новостей»), бэк возвращает данные. |
| **REST API** | Самый распространённый формат API. Запросы вида `GET /api/news`, `POST /api/tickets`. |
| **HTTP-методы** | `GET` — получить данные; `POST` — создать; `PUT/PATCH` — изменить; `DELETE` — удалить. |
| **JSON** | Формат данных, понятный и людям, и компьютерам: `{"name": "Иван", "age": 30}`. |
| **База данных (БД)** | Место, где хранятся все данные: пользователи, документы, чаты, новости. Как таблицы в Excel, только мощнее. |
| **SQL** | Язык запросов к БД: `SELECT * FROM users WHERE role = 'MEMBER'`. |
| **ORM** | Библиотека, которая позволяет работать с БД на TypeScript вместо SQL. У нас это **Prisma**. |
| **Миграция** | Изменение структуры БД: добавить колонку, создать таблицу. Как «версионирование» для базы данных. |

### Инфраструктура и деплой

| Термин | Что это значит |
|--------|---------------|
| **Сервер** | Компьютер, который работает 24/7 и отвечает на запросы пользователей. Наш сервер: `194.87.49.210`. |
| **VDS** | Virtual Dedicated Server — виртуальный сервер, который мы арендуем. Как обычный компьютер, но в дата-центре. |
| **SSH** | Способ подключиться к серверу удалённо через терминал. Команда: `ssh root@194.87.49.210`. |
| **Деплой (Deploy)** | Процесс «выгрузки» кода на сервер, чтобы пользователи увидели изменения. |
| **PM2** | Менеджер процессов на сервере. Следит, чтобы приложение работало, и перезапускает его при падении. |
| **Nginx** | Веб-сервер, который принимает запросы от пользователей и передаёт их нашему приложению. Как «приёмная» на входе. |
| **SSL/HTTPS** | Шифрование трафика. Замочек в адресной строке = данные защищены. |
| **DNS** | Система, которая превращает `myunion.pro` в IP-адрес `194.87.49.210`. |
| **CDN** | Content Delivery Network — раздача картинок и файлов из ближайшего к пользователю сервера. |

| Термин | Что это значит |

## 2. Что такое МойСоюз

**МойСоюз** (myunion.pro) — это веб-платформа для управления профсоюзными организациями.

### Что умеет система:
- **Регистрация и анкетирование** членов профсоюза
- **Генерация документов**: заявления, протоколы, выписки (PDF)
- **Заседания профкома**: повестка, голосование, протоколы
- **Корпоративный чат** (как Slack) с тредами, реакциями, файлами
- **Новости и посты** с лайками, комментариями, опросами
- **Обращения** (тикеты) в профком от членов
- **Скидки и привилегии** для членов профсоюза
- **ИИ-ассистент** — чат-бот с базой знаний профсоюза
- **Отчётность** (ежемесячная, квартальная, годовая)
- **Push-уведомления** (браузер, мобильные)
- **Авторизация** через SMS, Telegram, VK, Яндекс, Госуслуги, MAX

### Кто пользуется:
1. **Члены профсоюза** — заполняют анкету, получают скидки, общаются в чате
2. **Председатели ППО** — управляют организацией, проводят заседания, утверждают документы
3. **Сотрудники профкома** — бухгалтер, секретарь, специалисты
4. **Руководители МПО/РПО** — контролируют подчинённые организации, принимают отчёты
5. **Супер-админы** — управляют всей платформой

## 4. Архитектура проекта

### Общая схема

```
Пользователь (браузер/телефон)
    │
    ▼
Nginx (myunion.pro, SSL)
    │
    ├──► Next.js (PM2: my-union-pro, порт 3000)
    │       ├── Страницы (SSR/SSG)
    │       └── API Routes (/api/*)
    │
    ├──► Socket.IO (PM2: my-union-socket, порт 3005)
    │       └── Реалтайм чат
    │
    ├──► PostgreSQL (VK Cloud, 83.166.237.161:5432)
    │       └── Все данные (пользователи, документы, чаты...)
    │
    └──► Redis (localhost:6379)
            ├── Кэш сессий
            ├── Очереди задач (BullMQ)
            └── Pub/Sub для чата
```

### Как устроен бэкенд

Бэкенд в нашем проекте — это **API Routes** в папке `app/api/`. Каждый файл `route.ts` — это один endpoint.

**Пример: получить список новостей**

1. Браузер отправляет запрос: `GET https://myunion.pro/api/news`
2. Nginx перенаправляет запрос в Next.js
3. Next.js находит файл `app/api/news/route.ts`
4. Код в файле:
   - Проверяет авторизацию (есть ли сессия)
   - Запрашивает данные из БД через Prisma
   - Возвращает JSON с новостями
5. Браузер получает данные и отрисовывает их

- **Тип**: PostgreSQL
- **Хостинг**: VK Cloud (83.166.237.161:5432)
- **Имя БД**: `myunion_db`
- **ORM**: Prisma (`prisma/schema.prisma`)
- **Количество таблиц**: ~74 моделей

## 7. API — серверная логика

### Как устроены API-маршруты

Каждый файл `route.ts` в папке `app/api/` — это один или несколько endpoint'ов.

**Пример файла `app/api/news/route.ts`:**

```typescript
import { NextRequest, NextResponse } from "next/server";
import { getServerSession } from "next-auth";
import { authOptions } from "@/lib/auth";
import { prisma } from "@/lib/prisma";

// GET /api/news — получить список новостей
export async function GET(request: NextRequest) {
  // 1. Проверяем авторизацию
  const session = await getServerSession(authOptions);
  if (!session?.user?.id) {
    return NextResponse.json({ error: "Не авторизован" }, { status: 401 });
  }

  // 2. Получаем данные из БД
  const news = await prisma.newsPost.findMany({
    where: { isPublished: true },
    orderBy: { publishedAt: "desc" },
    take: 20,
  });

  // 3. Возвращаем JSON
  return NextResponse.json({ news });
}
```

### Основные группы API

| Путь | Что делает |
|------|-----------|
| `/api/auth/*` | Авторизация: SMS, email, VK, Яндекс, Telegram, MAX, ЕСИА |
| `/api/profile/*` | Профиль пользователя: чтение, обновление, аватар |
| `/api/documents/*` | Документы: генерация, загрузка, подпись |
| `/api/news/*` | Новости: публикации, лайки, комментарии, опросы |
| `/api/chat/*` | Чаты: создание, сообщения, участники, реакции |
| `/api/tickets/*` | Обращения: создание, ответы, закрытие |
| `/api/ppo-head/*` | API для председателя: члены, документы, заседания, отчёты |
| `/api/admin/*` | Админка: пользователи, организации, настройки |
| `/api/assistant/chat` | ИИ-ассистент: чат с ботом |
| `/api/push/*` | Push-уведомления: подписка, отправка |
| `/api/discounts/*` | Скидки: список, активация, синхронизация |

## 9. Авторизация

### Поддерживаемые методы входа

1. **SMS** — ввёл номер → пришёл код в SMS (или Telegram/MAX, если привязаны)
2. **Email** — ввёл email → пришла ссылка для входа (magic link)
3. **VK ID** — кнопка «Войти с VK ID» → OAuth через id.vk.ru
4. **Яндекс** — кнопка «Войти с Яндекс» → OAuth через Яндекс
5. **Telegram** — через бота @myunionpro_bot → кнопка входа
6. **MAX** — через мини-приложение в мессенджере MAX
7. **ЕСИА (Госуслуги)** — через Госуслуги (в разработке)
8. **Email + пароль** — для супер-админов

### Как работает авторизация

```
Пользователь нажимает "Войти"
    │
    ▼
Выбирает способ (SMS / VK / Яндекс / ...)
    │
    ├──► SMS: отправляется PIN-код → вводит код → NextAuth signIn("sms")
    ├──► VK ID: редирект на id.vk.ru → callback → создаётся LoginToken → signIn("login-token")
    ├──► Яндекс: редирект на Яндекс → callback → NextAuth signIn("yandex")
    └──► Telegram: бот отправляет кнопку → callback → LoginToken → signIn("login-token")
    │
    ▼
NextAuth создаёт JWT-сессию (cookie)
    │
    ▼
Пользователь авторизован → /dashboard
```

### Конфигурация

- Файл: `lib/auth.ts` — все провайдеры, callbacks
- Файл: `lib/vk-id-auth.ts` — VK ID OAuth 2.1 + PKCE
- Файл: `lib/telegram-bot.ts` — отправка сообщений в Telegram

## 11. Основные фичи системы

### Чат (реалтайм)

- **Протокол**: Socket.IO (WebSocket)
- **Сервер**: `server/chat-server.ts` (PM2: `my-union-socket`, порт 3005)
- **Типы чатов**: личные (PRIVATE), групповые (GROUP), каналы (CHANNEL)
- **Возможности**: треды, реакции, вложения, ответы, прочитано, онлайн-статусы
- **Redis**: используется для pub/sub и синхронизации между инстансами

### Генерация документов

- **Шаблоны**: HTML + CSS в таблице `DocumentTemplate`
- **Переменные**: `{{firstName}}`, `{{lastName}}`, `{{organizationName}}`
- **Рендеринг**: Puppeteer (headless Chrome) → HTML → PDF
- **Типы**: заявления, протоколы, выписки, постановления

### ИИ-ассистент

- **API**: `/api/assistant/chat` и `/api/chat/ai`
- **Провайдер**: Yandex Foundation Models (YandexGPT / YandexGPT-lite / yandexgpt-32k)
- **RAG**: поиск по базе знаний (векторные эмбеддинги 256-dim в `KnowledgeChunk`)
- **Настройка**: через админку — системный промт, модель, температура

### Уведомления

- **Push**: Firebase Cloud Messaging (FCM)
- **Email**: SMTP через Nodemailer
- **Telegram**: через Bot API (`lib/telegram-bot.ts`)
- **In-app**: таблица `UserNotification`

### Скидки

- **Синхронизация**: с BestBenefits API
- **Промо-коды**: генерация и активация
- **Категории**: автоматическая синхронизация

## 12. Рабочий процесс: от задачи до деплоя

### Алгоритм работы

```
1. Получить задачу в Linear
       │
       ▼
2. Прочитать и понять задачу
       │
       ▼
3. Продумать логику (что менять, где менять)
       │
       ▼
4. Открыть Cursor AI, описать задачу промтом
       │
       ▼
5. Проверить сгенерированный код (ОБЯЗАТЕЛЬНО!)
       │
       ▼
6. Протестировать локально (pnpm dev)
       │
       ▼
7. Закоммитить и задеплоить
       │
       ▼
8. Проверить на проде (https://myunion.pro)
       │
       ▼
9. Обновить задачу в Linear (статус: Done)
```

### Шаг 1: Получить задачу

Задачи приходят в **Linear** (linear.app). Каждая задача содержит:
- **Заголовок**: краткое описание
- **Описание**: подробности, что нужно сделать
- **Приоритет**: Urgent / High / Medium / Low
- **Статус**: Backlog → Todo → In Progress → Done

### Шаг 2: Понять задачу

Прежде чем писать код, ответь себе:
1. **Что** нужно сделать? (добавить кнопку / исправить баг / сделать API)
2. **Где** это находится? (какая страница / какой API / какая таблица в БД)
3. **Как** это должно работать? (сценарий пользователя от начала до конца)
4. **Что может сломаться?** (крайние случаи, ошибки)

### Шаг 3: Продумать логику

Пример задачи: *«Добавить возможность прикрепить файл к обращению»*

Разбиваем на шаги:
1. **БД**: в таблице `Ticket` или отдельной `TicketAttachment` уже есть поле для файла? → Смотрим `prisma/schema.prisma`
2. **API**: нужен endpoint для загрузки файла → `POST /api/tickets/[id]/attachments`
3. **UI**: на странице обращения добавить кнопку «Прикрепить файл» → `app/dashboard/appeals/[id]/page.tsx`
4. **Хранение**: куда сохранять файл? → VDS (`public/uploads/`)

### Шаг 4: Работа в Cursor AI

Открываешь Cursor, нажимаешь `Cmd+I` (Agent) и описываешь задачу. Подробнее — в разделе [14. Работа с Cursor AI](#14-работа-с-cursor-ai).

### Шаг 5: Проверить код

**ВСЕГДА** проверяй то, что сгенерировал ИИ:
- Нет ли ошибок TypeScript (`pnpm type-check`)
- Нет ли лишних console.log
- Правильно ли работает логика
- Не сломался ли другой функционал

## 14. Работа с Cursor AI

### Что такое Cursor AI

Cursor — это редактор кода (как VS Code), в который встроен ИИ-ассистент. Ты описываешь задачу на русском языке, а ИИ генерирует код, ищет по проекту, исправляет ошибки.

### Режимы работы

| Режим | Горячая клавиша | Когда использовать |
|-------|----------------|-------------------|
| **Agent** | `Cmd+I` | Для сложных задач: ИИ сам ищет файлы, пишет код, запускает команды |
| **Chat** | `Cmd+L` | Для вопросов: «Как работает авторизация?», «Где хранятся документы?» |
| **Edit** | `Cmd+K` | Для изменения выделенного кода: «Добавь обработку ошибки» |
| **Tab** | `Tab` | Автодополнение: ИИ предлагает продолжение кода |

### Как формулировать промты

#### Правило 1: Будь конкретным

```
❌ Плохо: "Сделай чтобы работало"
✅ Хорошо: "В файле app/api/tickets/route.ts добавь поле responseDeadline 
           (Date, nullable) при создании тикета. Дедлайн = 3 рабочих дня 
           от создания."
```

#### Правило 2: Указывай контекст

```
❌ Плохо: "Добавь кнопку"
✅ Хорошо: "На странице app/dashboard/appeals/[id]/page.tsx добавь кнопку 
           'Прикрепить файл' рядом с кнопкой отправки. Используй компонент 
           Button из HeroUI. При клике — открывать input type=file."
```

#### Правило 3: Описывай ожидаемый результат

```
✅ "После нажатия кнопки 'Сгенерировать протокол' на странице заседания:
   1. Отправить POST /api/ppo-head/meetings/[id]/generate-document
   2. Показать спиннер во время генерации
   3. При успехе — скачать PDF файл
   4. При ошибке — показать toast с текстом ошибки"
```

#### Правило 4: Указывай на существующие паттерны

```
✅ "Сделай API-маршрут /api/ppo-head/announcements по аналогии с 
   /api/ppo-head/news/route.ts — та же структура: проверка сессии, 
   проверка роли PPO_HEAD, работа с Prisma."
```

### Примеры промтов для типичных задач

#### Исправить баг

```
Промт: "На странице /dashboard/profile при сохранении профиля поле 
middleName (отчество) не сохраняется. Проверь API /api/profile (PUT метод) 
— передаётся ли middleName в data для prisma.user.update. Если нет — добавь."
```

#### Добавить поле в БД

```
Промт: "Добавь поле birthPlace (String, optional) в модель User 
в prisma/schema.prisma. Создай миграцию. Добавь это поле в форму 
профиля (components/profile/ProfileForm.tsx) и в API обновления профиля 
(/api/profile route.ts, PUT)."
```

#### Создать новую страницу

```
Промт: "Создай страницу /dashboard/certificates для просмотра сертификатов 
пользователя. Страница должна:
1. Загружать данные с GET /api/certificates
2. Показывать список карточек с названием и датой
3. Кнопка 'Скачать PDF' на каждой карточке
4. Использовать DashboardLayout, стилизация как на странице /dashboard/documents
5. API пока не создавай — сделай заглушку с тестовыми данными"
```

#### Деплой

```
Промт: "деплой"
```
Cursor AI знает скрипты деплоя и выполнит `commit-and-deploy.sh`.

### Что НЕ стоит делать

1. **Не доверяй ИИ слепо** — всегда проверяй код
2. **Не генерируй всё подряд** — сначала пойми задачу
3. **Не удаляй код, который не понимаешь** — спроси ИИ «что делает этот код?»
4. **Не деплой без проверки** — запусти `pnpm test` и `pnpm type-check`

## 18. Частые ошибки и как их решать

### Ошибка: `PrismaClientKnownRequestError: column does not exist`

**Причина:** В `schema.prisma` добавлено новое поле, но миграция не применена на сервере.

**Решение:**
```bash
# Локально: создать миграцию
pnpm prisma:migrate

# На сервере: применить миграцию
ssh root@194.87.49.210 'cd /opt/my-union-pro && npx prisma migrate deploy'

# Или: добавить колонку напрямую через SQL
ssh root@194.87.49.210 'cd /opt/my-union-pro && npx dotenv -e .env.local -- npx prisma db execute --schema prisma/schema.prisma --stdin <<EOF
ALTER TABLE "User" ADD COLUMN IF NOT EXISTS "newField" TEXT;
EOF'
```

---

### Ошибка: `Error: NEXTAUTH_SECRET is not set`

**Причина:** Не настроены переменные окружения.

**Решение:** Проверь `.env.local` — должен быть `NEXTAUTH_SECRET=ваш_секрет`.

---

### Ошибка: `504 Gateway Timeout` на проде

**Причина:** Приложение не запустилось или упало.

**Решение:**
```bash
ssh root@194.87.49.210
pm2 list                          # Проверить статус
pm2 logs my-union-pro --err       # Посмотреть ошибки
pm2 restart my-union-pro          # Перезапустить
```

---

### Ошибка: `Module not found: Can't resolve '@/lib/...'`

**Причина:** Файл не существует или неправильный путь.

**Решение:** `@/` = корень проекта. `@/lib/auth` = `lib/auth.ts`. Проверь, что файл есть.

---

### Ошибка: TypeScript — `Property 'X' does not exist on type`

**Причина:** Забыл добавить поле в тип или Prisma Client не обновлён.

**Решение:**
```bash
pnpm prisma:generate    # Обновить Prisma Client
pnpm type-check         # Проверить типы
```

---

### Ошибка: деплой зависает на `pnpm build`

**Причина:** Не хватает памяти на сервере или бесконечный цикл.

**Решение:**
```bash
ssh root@194.87.49.210
free -h                    # Проверить память
pm2 stop all               # Остановить процессы для освобождения памяти
cd /opt/my-union-pro
NODE_OPTIONS="--max-old-space-size=2048" pnpm build
pm2 restart all
```

## 20. FAQ — Часто задаваемые вопросы

### Q: Как узнать, какой файл менять для задачи?

**A:** Спроси в Cursor Chat (`Cmd+L`):
```
Где в проекте находится код, отвечающий за [описание функционала]?
```

### Q: Я сломал что-то. Как откатить?

**A:**
```bash
# Откатить последний коммит (до пуша)
git reset --soft HEAD~1

# Откатить изменения в файле
git checkout -- путь/к/файлу

# Откатить всё до последнего коммита
git checkout .
```

### Q: Как посмотреть логи на сервере?

**A:**
```bash
# Через SSH
ssh root@194.87.49.210 'pm2 logs my-union-pro --lines 50 --nostream'

# Или через скрипт
./check-deploy-status.sh
```

### Q: Как добавить новую переменную окружения на прод?

**A:**
```bash
ssh root@194.87.49.210
nano /opt/my-union-pro/.env.local
# Добавь переменную, сохрани (Ctrl+O, Ctrl+X)
pm2 restart my-union-pro
```

### Q: Как подключиться к БД напрямую?

**A:** Используй Prisma Studio (визуальный интерфейс):
```bash
pnpm prisma:studio
# Откроется в браузере на http://localhost:5555
```

### Q: Как создать тестового пользователя?

**A:** Зайди на https://myunion.pro/login, введи свой номер телефона. Код придёт в SMS.

### Q: Как тестировать на телефоне?

**A:** Локально — не получится (localhost). На проде — просто открой https://myunion.pro с телефона.

### Q: Сколько времени занимает деплой?

**A:** ~2 минуты: pre-deploy проверки (~20 сек) + сборка на сервере (~30 сек) + перезапуск (~10 сек).

### Q: Что делать если деплой упал?

**A:**
1. Прочитай ошибку в терминале
2. Если ошибка TypeScript — исправь тип и попробуй снова
3. Если ошибка Prisma — проверь миграции
4. Если сервер не отвечает — подключись по SSH и проверь `pm2 list`
5. Если ничего не помогает — спроси в Cursor: «Деплой упал с ошибкой: [текст ошибки]. Как исправить?»

### Q: Где хранится пароль от сервера?

**A:** В файле `vds.deploy.env` (в корне проекта, в `.gitignore`). Формат:
```bash
export VDS_PASSWORD='пароль'
```
Этот файл **НИКОГДА** не коммитится в Git. Попроси пароль у тимлида.
