# Система отслеживания сроков ответа на обращения

## Обзор

Система автоматически отслеживает сроки ответа на обращения и отправляет уведомления председателям о необходимости ответа. Также система автоматически закрывает обращения, если пользователь не ответил в течение 72 часов после ответа председателя.

## Основные функции

### 1. Отслеживание сроков ответа председателя

- При создании обращения автоматически устанавливается дедлайн ответа председателя: **72 часа** с момента создания
- Система отслеживает, когда председатель ответил на обращение
- Если дедлайн истек, обращение помечается как просроченное (`isOverdue = true`)

### 2. Отслеживание сроков ответа пользователя

- После ответа председателя устанавливается дедлайн ответа пользователя: **72 часа**
- Если пользователь не ответил в течение 72 часов, обращение автоматически закрывается без оценки обслуживания

### 3. Система уведомлений

#### Ежедневные напоминания (9:00 МСК)
- Каждый день в 9:00 по московскому времени система отправляет напоминания председателям обо всех открытых обращениях
- Напоминания отправляются через push-уведомления и email
- Для просроченных обращений используется более срочный заголовок

#### Уведомления о просрочке
- При обнаружении просроченного обращения система немедленно отправляет уведомление председателю
- Уведомление содержит информацию о просроченном обращении и требует срочного ответа

### 4. Автоматическое закрытие обращений

- Если пользователь не ответил в течение 72 часов после ответа председателя, обращение автоматически закрывается
- Статус обращения меняется на `CLOSED`
- В чат обращения отправляется системное сообщение о причине закрытия
- Оценка обслуживания (`helpfulRating`) не устанавливается

## Модель данных

### Поля в модели Ticket

```prisma
// Дедлайн для ответа председателя (72 часа с момента создания)
responseDeadline DateTime?

// Дата последнего ответа председателя
lastResponseAt DateTime?

// Дата последнего ответа пользователя (после ответа председателя)
lastUserResponseAt DateTime?

// Дедлайн для ответа пользователя (72 часа после ответа председателя)
userResponseDeadline DateTime?

// Флаг просроченного обращения
isOverdue Boolean @default(false)

// Дата последнего уведомления о просрочке
overdueReportedAt DateTime?

// Дата последнего напоминания (ежедневно в 9:00 МСК)
lastReminderSentAt DateTime?

// Дата автоматического закрытия
autoClosedAt DateTime?
```

## API Endpoints

### Крон-задача проверки сроков

**GET** `/api/cron/check-ticket-deadlines`

Проверяет сроки ответа на обращения и отправляет уведомления. Вызывается:
- Каждый час (для проверки просроченных обращений)
- Ежедневно в 9:00 МСК (для отправки напоминаний)

**Авторизация:**
- Заголовок `Authorization: Bearer {CRON_SECRET}`
- Query параметр `?secret={CRON_SECRET}`
- Заголовок `x-vercel-cron: true` (для Vercel Cron)

**Ответ:**
```json
{
  "success": true,
  "checked": 10,
  "overdue": 2,
  "reminders": 5,
  "autoClosed": 1,
  "duration": 1234
}
```

## Логика работы

### 1. Создание обращения

При создании обращения:
1. Устанавливается `responseDeadline = createdAt + 72 часа`
2. `isOverdue = false`
3. Остальные поля сроков = `null`

### 2. Ответ председателя

Когда председатель отправляет сообщение в чат обращения:
1. Обновляется `lastResponseAt = now()`
2. Устанавливается `userResponseDeadline = now() + 72 часа`
3. Сбрасывается `isOverdue = false` (если было установлено)

### 3. Ответ пользователя

Когда пользователь отправляет сообщение в чат обращения (после ответа председателя):
1. Обновляется `lastUserResponseAt = now()`
2. Сбрасывается `userResponseDeadline = null`

### 4. Проверка просрочки (крон-задача)

Каждый час:
1. Находятся обращения с `responseDeadline <= now()` и `isOverdue = false`
2. Помечаются как просроченные (`isOverdue = true`)
3. Отправляются уведомления председателям

### 5. Ежедневные напоминания (9:00 МСК)

Каждый день в 9:00 МСК:
1. Находятся все открытые обращения (`status IN ['PENDING', 'IN_PROGRESS']`)
2. Проверяется, не отправлялось ли напоминание сегодня (`lastReminderSentAt < 23 часа назад`)
3. Отправляются напоминания председателям

### 6. Автоматическое закрытие

Если `userResponseDeadline <= now()` и `autoClosedAt = null`:
1. Статус меняется на `CLOSED`
2. Устанавливается `autoClosedAt = now()`
3. Отправляется системное сообщение в чат

## Отчеты

### Статистика по обращениям

В отчеты добавлена информация о просроченных обращениях:
- Общее количество просроченных обращений
- Среднее время ответа председателя
- Среднее время решения обращения

### Функции аналитики

`lib/ticket-analytics.ts`:
- `getTicketAnalytics()` - общая статистика по обращениям
- `getOverdueTickets()` - список просроченных обращений

## Настройка крон-задачи

### Vercel Cron

Добавьте в `vercel.json`:

```json
{
  "crons": [
    {
      "path": "/api/cron/check-ticket-deadlines",
      "schedule": "0 6 * * *"
    },
    {
      "path": "/api/cron/check-ticket-deadlines",
      "schedule": "0 * * * *"
    }
  ]
}
```

- Первая задача: ежедневно в 9:00 МСК (6:00 UTC)
- Вторая задача: каждый час для проверки просрочки

### Другие платформы

Настройте cron-задачи для вызова:
- `GET /api/cron/check-ticket-deadlines?secret={CRON_SECRET}` - каждый час
- `GET /api/cron/check-ticket-deadlines?secret={CRON_SECRET}` - ежедневно в 9:00 МСК

## Уведомления

### Типы уведомлений

- `ticket_overdue` - Просрочено обращение
- `ticket_reminder` - Напоминание об обращении

### Настройки пользователя

Уведомления отправляются согласно настройкам пользователя:
- Push-уведомления: `pushNotificationsEnabled`
- Email-уведомления: `emailAppealNotifications`

## Примеры использования

### Получение просроченных обращений

```typescript
import { getOverdueTickets } from "@/lib/ticket-analytics";

const overdueTickets = await getOverdueTickets(organizationId);
console.log(`Просрочено обращений: ${overdueTickets.length}`);
```

### Получение статистики

```typescript
import { getTicketAnalytics } from "@/lib/ticket-analytics";

const analytics = await getTicketAnalytics(organizationId);
console.log(`Просрочено: ${analytics.overdue}`);
console.log(`Среднее время ответа: ${analytics.averageResponseTime} часов`);
```
