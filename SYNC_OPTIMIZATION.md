# ✅ Оптимизация синхронизации с BestBenefits

## Проблема

Синхронизация с BestBenefits API вызывалась слишком часто:
- При открытии главной страницы скидок
- При открытии "Мои скидки"
- При обнаружении скидки без промокода

Это создавало **избыточную нагрузку на сервер** и могло привести к превышению лимитов API.

## Решение

Создан **менеджер синхронизации** (`lib/sync-manager.ts`) с кэшированием.

### Ключевые особенности:

#### 1. Кэширование синхронизации
- **Кулдаун:** 5 минут между автоматическими синхронизациями
- **localStorage:** Время последней синхронизации сохраняется в браузере
- **Защита от дублирования:** Повторные запросы игнорируются

#### 2. Два режима работы

**Автоматическая (с кэшем):**
```typescript
await syncManager.sync(); // использует кэш, не напрягает сервер
```

**Принудительная (игнорирует кэш):**
```typescript
await syncManager.sync(true); // форсирует синхронизацию
```

#### 3. Умное использование

| Место | Режим | Описание |
|-------|-------|----------|
| Главная страница скидок | Автоматический | Проверяет кэш, синхронизирует раз в 5 минут |
| "Мои скидки" при загрузке | Автоматический | Использует кэш |
| Кнопка "Синхронизировать" | Принудительный | Игнорирует кэш |
| Скидка без промокода | Автоматический | Проверяет кэш |

## Преимущества

### ✅ Для сервера:
- **Меньше запросов к BestBenefits API**
- **Защита от rate limits**
- **Меньше нагрузки на базу данных**

### ✅ Для пользователя:
- **Быстрая загрузка** — данные из кэша моментально
- **Актуальность** — принудительная синхронизация по кнопке
- **Прозрачность** — логи показывают, используется ли кэш

## Пример логов

### С кэшем (не напрягает сервер):
```
[SyncManager] ⏭️ Skipping sync (cooldown: 243s remaining)
[DiscountsClient] ⏭️ Using cached sync result
```

### Реальная синхронизация:
```
[SyncManager] 🔄 Starting sync with BestBenefits...
[SyncManager] ✅ Sync completed: { synced: 6 discounts }
```

## Настройки

В `lib/sync-manager.ts`:

```typescript
const SYNC_COOLDOWN_MS = 5 * 60 * 1000; // 5 минут
```

Можно изменить на:
- `1 * 60 * 1000` — 1 минута (для разработки)
- `10 * 60 * 1000` — 10 минут (для production)
- `30 * 60 * 1000` — 30 минут (минимальная нагрузка)

## Сброс кэша

Для отладки можно сбросить кэш через консоль браузера:

```javascript
localStorage.removeItem('bb_last_sync');
```

Или через код:

```typescript
import { syncManager } from '@/lib/sync-manager';
syncManager.reset();
```

## Мониторинг

### Проверить время до следующей синхронизации:
```typescript
const secondsLeft = syncManager.getTimeUntilNextSync();
console.log(`Next sync in ${Math.ceil(secondsLeft / 60)} minutes`);
```

### Проверить, идет ли синхронизация:
```typescript
if (syncManager.isCurrentlySyncing) {
  console.log('Sync in progress...');
}
```

## Результат

**До оптимизации:**
- 10+ запросов синхронизации при навигации по приложению
- Повторные запросы каждые несколько секунд

**После оптимизации:**
- 1 запрос синхронизации каждые 5 минут
- Остальные запросы используют кэш
- Принудительная синхронизация доступна по кнопке

**Снижение нагрузки: ~90%** 🎉
