# Система валидации данных через чат-бота

## Обзор

Чат-бот использует комплексную систему валидации данных через внешние API и справочники для обеспечения качества и корректности информации.

## Валидации

### 1. ФИО (через DaData) ✅ НОВОЕ!

**Что проверяется:**
- Корректность написания фамилии, имени, отчества
- Нормализация ФИО (приведение к правильному регистру)
- Поддержка тюркских суффиксов ("улы", "оглы", "кызы")

**Как работает:**
1. Пользователь вводит ФИО: "иванов иван иванович"
2. Система отправляет запрос в DaData Clean API
3. DaData возвращает нормализованное ФИО: "Иванов Иван Иванович"
4. Бот показывает пользователю исправленное ФИО для подтверждения

**Fallback:**
Если DaData недоступен, система использует простой парсинг (разбивка по пробелам).

---

### 2. Адрес (через DaData) ✅

**Что проверяется:**
- Корректность адреса
- Стандартизация формата
- Автоматическое извлечение города для скидок

**Как работает:**
1. Пользователь вводит адрес: "Татарстан, Челны, Чулман 11-141"
2. Система отправляет запрос в DaData Suggest API
3. DaData возвращает полный адрес: "Республика Татарстан, город Набережные Челны, проспект Чулман, дом 11, квартира 141"
4. Извлекается город: "Набережные Челны"
5. Бот показывает полный адрес для подтверждения
6. После подтверждения сохраняется:
   - `address`: полный адрес
   - `preferredDiscountCity`: "Набережные Челны"

---

### 3. Организация (через Минюст РФ) ✅

**Что проверяется:**
- Существование организации в реестре Минюста РФ
- Полное официальное название

**Как работает:**
1. Пользователь вводит: "БСМП Челны"
2. Система ищет в реестре Минюста (с учётом региона пользователя)
3. Находит: "ПРОФСОЮЗНАЯ ОРГАНИЗАЦИЯ РАБОТНИКОВ ГАУЗ БСМП Г.НАБЕРЕЖНЫЕ ЧЕЛНЫ"
4. Бот показывает полное название для подтверждения
5. После подтверждения:
   - Сохраняет организацию в БД (если новая)
   - Привязывает пользователя к организации

---

### 4. Должность (через справочник) ✅ НОВОЕ!

**Что проверяется:**
- Наличие должности в справочнике (142 должности)
- Автоматическое исправление опечаток и сокращений

**Справочник включает:**
- Медицину: Главный врач, Врач-терапевт, Медицинская сестра...
- Образование: Директор школы, Учитель, Воспитатель...
- IT: Программист, Системный администратор...
- Производство: Мастер, Технолог, Инженер...
- Управление: Генеральный директор, Начальник, Менеджер...
- И другие сферы

**Как работает:**
1. Пользователь вводит: "врач" или "Врач-тера"
2. Система ищет в справочнике (точное совпадение или частичное)
3. Находит: "Врач-терапевт"
4. Бот показывает найденную должность
5. На странице профиля - автокомплит с выпадающим списком

---

### 5. Профессия (через справочник) ✅ НОВОЕ!

**Что проверяется:**
- Наличие профессии в справочнике (95 профессий)
- Стандартизация названия

**Справочник включает:**
- Медицину: Врач, Медицинская сестра, Фельдшер...
- Образование: Учитель, Преподаватель, Воспитатель...
- IT: Программист, Системный администратор...
- Производство: Токарь, Сварщик, Технолог...
- Торговлю: Продавец, Кассир, Товаровед...
- И другие сферы

**Как работает:**
1. Пользователь вводит: "медсестра" или "мед"
2. Система ищет в справочнике
3. Находит: "Медицинская сестра"
4. Бот показывает найденную профессию
5. На странице профиля - автокомплит

---

## Автокомплит в профиле

На странице редактирования профиля поля "Должность" и "Профессия" имеют **автокомплит с выпадающим списком**:

- Начните вводить минимум 2 символа
- Появится выпадающий список подходящих вариантов
- Список **выровнен по левому краю** поля ввода (не по центру!)
- Можно выбрать мышкой или клавишами ↑↓ + Enter
- Список отсортирован по алфавиту

## Контекстная система

Система определяет контекст вопроса бота и применяет соответствующую валидацию:

```typescript
enum BotQuestionContext {
  FIO,           // → validateNameWithDaData()
  ADDRESS,       // → validateAddressWithDaData()
  ORGANIZATION,  // → findOrganization()
  JOB_TITLE,     // → findJobTitle()
  PROFESSION,    // → findProfession()
  // ... другие контексты
}
```

## Защита от зацикливания

**Проблема:** Бот мог спрашивать подтверждение несколько раз.

**Решение:**
1. В системном промпте добавлено **🚨🚨🚨 КРИТИЧЕСКИ ВАЖНОЕ ПРАВИЛО №1**: НЕ СПРАШИВАЙ ДВАЖДЫ
2. Перед каждым вопросом AI инструктирован проверять историю сообщений
3. Если поле уже подтверждено (получен ответ "да") - НЕ спрашивать снова

## API Endpoints

### GET /api/dictionaries

Возвращает списки профессий и должностей для автокомплита:

```json
{
  "jobTitles": ["Врач", "Главный врач", "Директор", ...],
  "professions": ["Врач", "Учитель", "Программист", ...]
}
```

---

## Расширение справочников

Для добавления новых профессий/должностей:

1. Откройте `prisma/seed-dictionaries.ts`
2. Добавьте в массивы `commonProfessions` или `commonJobTitles`
3. Запустите: `npx tsx prisma/seed-dictionaries.ts`

Справочники автоматически обновятся в БД.

Создайте тестовую сессию:

```bash

```

- Тестового пользователя

- Покажет ссылку для ручного тестирования

**Что проверять:**
- ✅ ФИО корректируется через DaData
- ✅ Адрес стандартизируется через DaData
- ✅ Организация находится в Минюсте
- ✅ Должность/профессия автозаполняются из справочника
- ✅ Бот НЕ спрашивает дважды
- ✅ Бот НЕ зацикливается
- ✅ Документы генерируются после подтверждения
